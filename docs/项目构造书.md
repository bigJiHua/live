## 第 0 章 · 十分钟上手

### 0.1 这份工程到底是什么

- **它是产品**：Gold 财管（个人财务管理 App）的移动端。
- **它是复刻**：不是重新设计，而是把 `web/` 的页面**一屏一屏**用原生组件重画，要求「逻辑 / 展示 / 交互一致」。
- **它已经能跑**：89 个路由目的地已注册、14 个业务域已落地、约 4.6 万行 Kotlin。

## 第 1 章 · 项目定位与三库关系

### 1.1 三条前端线（最容易混淆，务必先分清）

`D:\Code\live` 下有同一套产品的三个前端：

| 目录 | 技术 | 定位 | 本次是否改动 |
|---|---|---|---|
| `web/` | Vue 3 + Vant 4.9.22 + Pinia + vue-router + Vite（PWA） | **唯一真相源（source of truth）**：功能最全。「应该长什么样、点了发生什么、调哪个接口」一律以它为准 | **只读比对**，不改 |
| `webview-APP/` | Vue 3 打包 + uni-app / HBuilder 套壳 | 现有生产交付的 **H5 套壳 App**（`com.goldenfinance.app`，versionName 2.1.0），非原生 | 不改；作为并行参照 / 回退方案 |
| `APP/` | Kotlin + Jetpack Compose | **本次交付物**：原生重写，目标是替换套壳 App | 主战场 |

另有 `api/`（Node + Express + MySQL 后端，REST 前缀 `/api/v1`）：**所有客户端共用，本次不动，只作契约来源**。

### 1.2 核心工作方式：先复刻底座，再用底座搭业务

```
Vant 组件（web）  ──1:1 复刻──►  vant-ui（Compose 组件库）
                                       │
web/src/views/*.vue ──逐屏复刻──►  app/ui/<域>/*Screen.kt（只调用 Van* 组件）
                                       │
web/src/utils/api/*.js ──契约对齐──►  app/data/repo/*Repository.kt ──► api/（真后端）
```

这带来的最大好处：**原生 UI 结构与 web 高度同构**，看 web 的 `.vue` 就能猜到原生该写什么，迁移与排错成本都低。

### 1.3 两条不可动摇的原则

1. **真相源原则**：任何「长什么样 / 什么行为 / 什么字段」的疑问，去读 `web/src` 与 `api/src`，**不许臆造**。历史记忆里明确记着：曾因臆造接口（`accountBalance/upsert`、`account DELETE`、非分期的 `recurring/enter`）而返工。
2. **只读 web、慎动底座**：`web/` 不重构；`vant-ui` 尽量不动（除非真机不可编译这类硬阻塞）。

### 2.2 三个 Gradle 模块

| 模块 | Gradle 类型 | 包名 | 职责 | 依赖关系 |
|---|---|---|---|---|
| `:vant-ui` | `com.android.library` | `com.live.vant` | Vant 组件的 Compose 1:1 复刻，含主题与图标字体 | 无（只依赖 Compose / Coil） |
| `:app` | `com.android.application` | `com.live.finance` | 业务 App（导航、登录、各业务域） | `implementation(project(":vant-ui"))` |
| `:demo` | `com.android.application` | `com.live.vant.demo` | 组件可视化演示，用于「组件有没有画对」的快速验证 | `implementation(project(":vant-ui"))` |

依赖方向是单向的：`app → vant-ui ← demo`。**业务代码不得绕过 `Van*` 直接写底层控件**（会破坏与 web 的同构性）。

### 2.3 规模实况（2026-09-18 核对）

| 模块 | `.kt` 文件 | 代码行数 | 说明 |
|---|---|---|---|
| `vant-ui` | 46 | ≈ 6,863 | 45 类组件 + 7 类函数式 API + 3 个键盘扩展 |
| `app` | 163 | ≈ 39,362 | 其中 `ui/` 下 104 个屏幕/通用件 |
| `demo` | 2 | — | 演示壳 |
| **合计** | **211** | **≈ 46,225** | — |

对照侧规模：`web/src/views` **94 个 `.vue`**、`web/src/components` 18 个基础组件、`web/src/utils/api` 16 个接口模块。

### 2.4 双 flavor：`fake` 与 `prod`

`app/build.gradle.kts` 定义了两个 productFlavor，是**本地开发与真机联调的分水岭**：

| flavor | `BASE_URL` | `USE_FAKE` | 用途 |
|---|---|---|---|
| `fake` | `http://10.0.2.2:666/` | `true` | 全部仓库返回本地写死的演示数据，**无后端也能跑通主干** |
| `prod` | `http://192.168.0.103:666/` | `false` | 走 `ApiClient` 连真后端（当前是局域网地址） |

- Android Studio 里用 **Build Variants** 面板切 `appFake` / `appProd`。
- 切哪个 flavor，`AppGraph` 就注入哪套仓库实现——业务层代码**完全不需要改**。
- ⚠ **上线前必须**把 `prod` 的 `BASE_URL` 改成 `https://live.jihau.top` 并确认 HTTPS 与加密隧道。

## 第 3 章 · 技术栈与版本矩阵

### 3.1 版本矩阵（**禁止随手升级**）

| 项 | 版本 | 备注 |
|---|---|---|
| 语言 | Kotlin **1.9.24** | JVM target 17 |
| UI | Jetpack Compose **BOM 2024.06.00** | Compose 编译器扩展 **1.5.14** |
| 构建 | Gradle 8.x + **AGP 8.5.2** | Kotlin DSL（`.kts`） |
| Android | compileSdk **34** / minSdk **24** / targetSdk 34 | — |
| 导航 | `navigation-compose` 2.7.7 | — |
| 网络 | Retrofit 2.11 + OkHttp 4.12 + **Gson 2.11** | **未用** Kotlinx Serialization 转换器（避免额外编译器插件） |
| 协程 | `kotlinx-coroutines-android` 1.8.1 | — |
| 本地存储 | `datastore-preferences` 1.1.1 | 存 token / 指纹 / 主题选择 |
| 图片 | Coil（由 `vant-ui` 传递引入） | — |
| versionName | `0.1.0-wave0` | — |

### 3.2 为什么锁版本

**Compose 编译器扩展版本必须与 Kotlin 版本严格配对**（1.5.14 ↔ 1.9.24）。任何一个漂移都会导致全工程编译失败。因此：

- 新增依赖前先确认它不引入新的 Kotlin/Compose 编译器插件；
- 升级 Kotlin 必须同步升级 Compose 编译器扩展与 BOM，并重跑全量编译；
- 业务代码**不需要**、也**不应该**新增构建插件。

### 3.3 主题与图标的「可再生」资产

有两类资产不是手写的，改了 Vant 版本就必须重新生成，否则图标码点 / 主题色会漂移：

| 资产 | 位置 | 来源 | 再生成方式 |
|---|---|---|---|
| 图标字体 | `vant-ui/src/main/res/font/vant_icon.ttf` | `web/node_modules/vant/lib/index.css` 内嵌的 `@font-face vant-icon`（woff2） | fontTools 转 TTF（脚本见 `APP/README.md`） |
| 图标码点表 | `vant-ui/.../icon/VantIconCodes.kt` | 同上 CSS 的 `.van-icon-xxx:before{content:"\eXXX"}` | 正则提取 → JSON → Kotlin（需 `pip install fonttools brotli`） |
| 主题 Token | `vant-ui/.../theme/VantColors.kt` | `web/src/assets/css/style.css` 的 `--van-*` 覆盖 | 逐值对齐（人工） |

> ⚠ **AAPT 禁止 XML 注释里出现 `--`**：写 `--theme-bg-primary` 会让资源合并失败（见第 8 章）。这条只影响 XML 资源文件，不影响 Kotlin 与 Markdown。

## 第 4 章 · 架构分层与数据流

### 4.1 分层总览

```
        ┌──────────────────────────────────────────────┐
        │  ui/  （Compose 屏幕，按业务域分包）           │
        │  只用 Van* 组件 + FText/AppTokens 取色         │
        └───────────────┬──────────────────────────────┘
                        │ 调用（LaunchedEffect / 事件回调）
        ┌───────────────▼──────────────────────────────┐
        │  di/AppGraph.kt （手写 DI，按 useFake 选择实现）│
        └───────────────┬──────────────────────────────┘
                        │
        ┌───────────────▼──────────────────────────────┐
        │  data/repo/*Repository.kt                    │
        │  ├── FakeXxxRepository  （本地演示数据）       │
        │  └── RemoteXxxRepository（走网络）            │
        │  data/model/*.kt （数据类 + 解析）             │
        └───────────────┬──────────────────────────────┘
                        │
        ┌───────────────▼──────────────────────────────┐
        │  core/net/ApiClient.kt                       │
        │  （握手 / AES 信封 / 拦截 / 重试 / 429 / PIN） │
        └───────────────┬──────────────────────────────┘
                        │ HTTP
                    api/（Express 后端，REST /api/v1）
```

**关键约定**：屏幕层**不直接**发网络请求，一律经 `AppGraph` 拿到仓库；仓库层负责把后端 `snake_case` 字段映射成 Kotlin 数据类。

### 4.2 `core/` 基础设施文件职责

| 文件 | 职责 | 对应 web 侧 |
|---|---|---|
| `core/AppConfig.kt` | 编译期注入的配置（`BASE_URL` / `USE_FAKE` / 文件地址拼接 `fullFileUrl()`） | `web/src/utils/env.js` |
| `core/nav/Routes.kt` | **全量路由常量**，逐条对齐 web `router/map.js`；各域只引用这里的常量 | `web/src/router/map.js` |
| `core/net/ApiClient.kt` | **网络核心**：Retrofit + OkHttp，封装握手、加密信封（`{_p}`）、GET 明文 / 写操作加密、KEY_ERR 与 401 自动重握手 | `web/src/utils/request/**` |
| `core/net/HandshakeManager.kt` | 与后端握手（取会话密钥、注册设备指纹），`scene` 参数协商 | `web/src/utils/request/handshake.js` |
| `core/net/Envelope.kt` | 前后端标准信封 `{status,message,data}` 解析为 `ApiResult` | `web/src/utils/request/interceptors/response.js` |
| `core/net/DeviceProfile.kt` | 设备指纹采集（`X-FP-ID`、机型、系统等 header） | `utils/device-hash.js` + `securityHeaders.js` |
| `core/crypto/AesCbc.kt` | AES-256-CBC 加解密（与 web / 后端密钥派生一致） | `web/src/utils/aes.js` |
| `core/crypto/RsaUtil.kt`、`core/security/RsaUtil.kt` | RSA 工具（握手公钥、PIN 密文） | `jsencrypt` 用法 |
| `core/store/SessionStore.kt` | 登录会话（token / 用户态），基于 DataStore | `stores/user.js` + `localStorage.finance_token` |
| `core/ThemeStore.kt` | 主题状态（亮暗 / 主色预设）集中管理 | `composables/useUiTheme.js` |
| `core/PinCoordinator.kt` | PIN 锁屏/拦截协调（与 `SecurityRepository` 配合） | `components/PinVerifyDialog.vue` + `utils/request/pin.js` |
| `core/TimeFmt.kt` | 时间格式化 | `dayjs` 用法 |

### 4.3 `data/` 数据层

- **`data/model/`（20 个文件）**：`AssetRegister` `Balance` `Bill` `Card` `Category` `DbAdmin` `FixedBudget` `Foreign` `Fund` `Installment` `LoginLog` `Models`（聚合根） `Moment` `Pool` `Recurring` `Repay` `Resource` `Salary` `Stats` `TodoJob`。
- **`data/repo/`（19 个文件）**：每个域一个仓库，**全部是 Fake + Remote 双实现**：
  `AssetRepository` `AuthRepository` `BalanceRepository` `BillRepository` `CardRepository` `CategoryRepository` `DataRepository` `FixedBudgetRepository` `FlowRepository` `ForeignRepository` `FundRepository` `LoginLogRepository` `MomentRepository` `PoolRepository` `RecurringRepository` `RepayRepository` `ResourceRepository` `SecurityRepository` `TodoWorkRepository`。
- **切换开关**：`AppConfig.useFake == true` → 所有仓库返回本地演示数据（无需后端即可跑通主干）；`false` → 走 `ApiClient` 连真后端。
- **分包铁律**：`data/model/X.kt` 的包是 `data.model`，`data/repo/XRepository.kt` 的包是 `data.repo`，**必须分成两个文件**（历史踩坑：合并会导致包名错乱）。

### 4.4 `theme/` 主题层（10 套预设 + 收支配色）

### 4.6 网络协议（与 web 后端等价）

> 这是整个工程**最复杂、最容易出错**的部分。改造网络相关代码前，请先读 `api/src/utils/`（后端侧）与 `web/src/utils/request/**`。

**① 安全 Headers（每个请求都带）**

```
X-Requested-With: XMLHttpRequest
x-client-timestamp:  <毫秒时间戳>          # 后端容忍 ±2 分钟
x-fingerprint-hash:  <设备指纹 fp>
x-user-agent-custom / x-device-model / x-os-name / x-device-type
Authorization: Bearer <token>              # token 存在时
Content-Type: application/json             # FormData 上传时跳过加密走 multipart
```

**② 握手与密钥生命周期**

- `GET {base}/auth/handshake?fp=<fp>` → `{ status:200, key, scene, rsaPublicKey }`。
- `key` 是 **64 位十六进制字符串 = 32 字节 = AES-256**。
- 后端按 `fingerprint + scene` 存 key，有效期 **2 小时**；过期或解密失败时**重新握手**，并发时用「握手锁」防止重复请求。
- ⚠ **指纹必须稳定**：fp 变化会导致后端密钥记录漂移 → 解密失败。原生侧用稳定标识（`ANDROID_ID` 或首启自造的持久 UUID）。

**③ 加密载荷格式（逐字节必须一致）**

| 项 | 值 |
|---|---|
| 算法 | AES-256-CBC + PKCS7（= PKCS5）padding |
| 明文 | `JSON.stringify({ ...deviceData, data: <业务body>, path: <页面路径> })` |
| 密文线格式 | `IV_hex(32位小写hex) + base64(密文)`（前 32 字符就是随机 IV） |
| 编码 | UTF-8；密文 Base64 **不换行**（`Base64.NO_WRAP`） |

**加密范围**：写操作（`post` / `put` / `delete`）加密；GET 读操作只带 headers 不加密。
**不加密**：`/auth/handshake` 自身、`/auth/lock-system`、`/data-manager/import/sql`、FormData / 文件上传、下载导出（二进制透传）。

**④ 响应拦截规则**

| 后端返回 | 原生处理 |
|---|---|
| `status ∈ {200, 202}` 或 `success` | 成功（`ApiResult.Ok`）；写操作自动弹 success toast |
| `status == 202` 的写操作 | 成功但不弹 toast |
| `ismessage === true` | 原样返回，不弹窗（⚠ 见第 8 章陷阱） |
| HTTP 401 或业务体 `status:401` | 清 token → 重置导航栈到登录页（带防抖） |
| **429** | 跳 `Routes.ERROR_429`（频率限制兜底页） |
| 无响应（断网） | 「网络异常」toast |

**⑤ PIN 二次校验（830x 拦截链路）**

需要 PIN 保护的接口（如删除类）返回 `8303` 时：

1. 请求被**拦下**（不失败、不丢失），弹 PIN 输入；
2. `POST /security/pin/route-verify { pin, challengeId, requestUrl, method }` → 成功返回 `8301 { token, headerName: "x-route-verify-token" }`；
3. 带上该 header **原样重发**原始请求（服务端会做 stableStringify 哈希校验）。

其他码：`8302` 验证错误、`8304` 锁定→登出、`8301` 通过。`/security/pin/route-verify` 自身不再触发拦截（防递归）。
> 8303 有**两种语义**（`route_verify` 路由校验 vs 普通 `verify`），`AppRoot.PinGateHost` 按 `action_type` 分流，别混。

## 第 6 章 · 改造操作手册

### 6.0 动手前的铁律：先读契约，不猜

改任何域之前，**先对齐三处**（这是历史返工的主要来源）：

1. **web 调用点**：`web/src/utils/api/<域>.js` —— 路径、参数、请求/响应字段名。
2. **后端真相**：`api/src/modules/<域>/{api,controller,model}` —— 真实路由、`req.body.data` 读法、SELECT 别名/计算列、Joi 校验、枚举。
3. **已有原生实现**：`data/repo/<域>Repository.kt` + `ui/<域>/` —— 是否已经有人做过。

> 历史教训：曾因**臆造接口**而返工（`accountBalance/upsert`、`account DELETE`、非分期的 `recurring/enter` 都被删掉过）。
> 若本地后端在跑，可用 `curl` 带 APP 同款安全头（`X-Requested-With`、`x-client-timestamp` ±2min、`x-fingerprint-hash`、`x-user-agent-custom` 与 UA 一致）自检路由是否存在——放行后返回 `200 + {status:401}` 即证明「路由存在且鉴权生效」。

### 6.1 新增一个页面（标准四步）

```kotlin
// ① core/nav/Routes.kt —— 加常量（带参数用「模板 + 构造函数」成对写法）
const val XXX_DETAIL = "xxx/detail/{id}"
fun xxxDetail(id: String) = "xxx/detail/$id"

// ② ui/<域>/XxxScreen.kt —— 写屏幕（只用 Van* 与 AppTokens 取色）
@Composable fun XxxScreen(nav: NavHostController) {
    ScreenScaffold { m ->                       // ⚠ 签名见第 8 章 P0
        Column(m) {
            VanNavBar(title = "标题", leftArrow = true, onClickLeft = { nav.popBackStack() })
            /* 内容 */
        }
    }
}

// ③ ui/AppRoot.kt —— 在 NavHost 里注册
composable(Routes.XXX) { XxxScreen(nav) }

// ④ 入口处跳转（首页卡片 / 账本入口 / 「我的」MenuRow）
nav.navigate(Routes.XXX)
```

**带参数的页面**（照现有写法）：

```kotlin
composable(
    route = "${Routes.ASSETS_EDIT}?id={id}",
    arguments = listOf(androidx.navigation.navArgument("id") { defaultValue = "" }),

```

> ⚠ **注册用模板、跳转用填参**（`Routes.ASSETS_EDIT` 是模板，`Routes.xxxDetail(id)` 才是填好的路径）。
> ⚠ **`nav.navigate()` 的目标必须已注册**，否则运行时抛异常直接闪退（见第 8 章 P0）。

### 6.2 新增一个业务域

按顺序落 6 处，缺一处就会编译不过或点不进去：

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `data/model/X.kt` | 数据类 + JSON 解析（包名 `com.live.finance.data.model`） |
| 2 | `data/repo/XRepository.kt` | `interface XRepository` + `FakeXRepository` + `RemoteXRepository`（包名 `com.live.finance.data.repo`） |

| 5 | `ui/AppRoot.kt` | 注册路由 |
| 6 | 入口处 | 首页 / 账本 / 「我的」的 `MenuRow` 或卡片按钮 |

> **分包铁律**：`data/model/X.kt` 与 `data/repo/XRepository.kt` **必须分成两个文件**（历史踩坑）。
> **接口层**：每个域建议 `ApiXxx` 接口 + `Remote` 实现；`AppGraph` 里按 `useFake` 二选一。

### 6.3 新增 / 修改组件

- 组件放 `vant-ui/src/main/java/com/live/vant/<分组>/VanXxx.kt`，分组沿用 `basic / form / feedback / nav / layout / other`。
- **颜色必须取自 `theme/VantColors` 的 token**（否则深色模式会不一致）；不要硬编码十六进制。
- 改完先对照 `web/src/assets/css/style.css` 是否也有对应的 `--van-*` 覆盖——避免做出 web 没有的样式。
- 若只是业务级复用件（不是 Vant 语义），放 `app/ui/common/` 或该业务域目录，**不要塞进 `vant-ui`**。
- 新增/调整组件后，可在 `demo` 模块里加一页预览来肉眼验收。

### 6.4 接一个接口

```kotlin
// Remote 实现里：ApiClient 是统一的出入口（握手、加密信封、重试都由它处理）
val r = api.post("/xxx/create", body)          // body 是 JsonObject；无体传 JsonObject()
when (r) {
    is ApiResult.Ok -> { val d = r.data; if (d != null) { /* ⚠ data 是 T? 可空 */ } }
    is ApiResult.Fail -> toast.show(r.message ?: "操作失败")
}
```

要点：
- **写操作**（post/put/delete）自动加密，GET 明文——**不需要**在业务里手写加解密。
- `ApiClient.post/put/delete` **只收 `JsonObject`**（没有无体重载，无体时传 `JsonObject()`）。
- 字段映射在 Repository 里做：后端 `snake_case` → Kotlin 数据类；必要时兼容两套命名（`card_type || cardType`、`bill_day ?? billDay`）。
- 删除类接口常挂 `pinLockGuard`：`ApiClient` 会自动完成「8303 → PIN 验证 → 带令牌重发」三步，业务层无感。

### 6.5 改主题 / 颜色

1. 改预设或 token：`app/.../theme/ThemePreset.kt` / `AppTokens.kt`，**同时**核对 `web/src/composables/useUiTheme.js`。
2. 收支配色：`theme/MoneyColors.kt` ↔ `useMoneyColor.js`。
3. 页面取色一律 `LocalAppTokens.current` / `LocalAppColors.current`：
   - 颜色属性名是 **`bgCard` / `bgThird`**（没有 `bgSecondary` / `bgTertiary`）。
   - `LocalAppColors.current` 的类型是 `VantColors`，主色渐变字段是 **`primaryGrad`**；`AppTokens.grad` 是另一个东西，别混。
4. **Vant 语义色要暗色感知**：web 在暗色下把一批 Vant 别名变量重定向到主题色（`--van-green`→success、`--van-blue`→primary、`--van-danger-bg`→`#fff0f0`、`--van-green-bg`→`#f0f9eb`、`--van-orange-bg`→`rgba(255,151,106,.12)`，暗色才有值）。凡是照这些变量取色的地方都要做明暗分支。

### 6.6 改完怎么验证

```powershell
# 1) 编译（prod + fake 两个变体，见 0.4）
# 2) 只看错误与结论
Select-String -Path D:\Code\live\temp\appbuildNN.log -Pattern '^e: file|^e: |BUILD SUCCESSFUL|BUILD FAILED'
```

**判读规则（重要）**：

- `BUILD SUCCESSFUL` + 0 条 `e:` = 通过。
- **整包红灯时要先按文件分组看归属**：如果所有 `e:` 都落在别人的在途文件里，你自己的域就是干净的，**不要动别人正在改的文件**。
- 「0 条 `e:` 却 BUILD FAILED」= 并行构建竞态（非代码错误），错峰重跑即绿（见第 8 章 P3）。
- 报错信息里 `e: file:///.../Xxx.kt:LINE:COL` 精确到行列，直接定位。

**交付口径**：本工程只负责「编译通过 + 两个变体出 APK」。**真机安装、运行、视觉验收由使用者完成**——不要跳过这一步。

### 6.7 并行协作纪律（多人 / 多会话同时改）

历史经验（`.codebuddy/memory` §3）总结出的四条：

1. **用文件修改时间判断谁在写**：动手前 `mtime` 看一眼目标文件；共享底座（`ui/common/*`、`ui/AppRoot.kt`、`ui/main/MainScreen.kt`、`vant-ui/*`）尽量不改。
2. **私有件写页面内 `private`**：减少与他人撞名的概率。
3. **判据是「报错清单里没有我的文件」**：别人在途文件只做「解除阻塞的最小改动」，改完**立刻复核**是否与对方重复改动。
4. **并行跑 Gradle 会撞产物竞态**：出现 `dexBuilder/desugar_graph ... 系统找不到指定的路径` + `Detected multiple Kotlin daemon sessions` 时，等对方结束或错峰重跑。

## 第 7 章 · 注意事项（规则与边界）

### 7.1 必须 / 禁止

**MUST**

- 一切以 `web/src` + `api/src` 为准，动手前先读对应 `.vue` 与 `utils/api/*.js`。
- 业务 UI 只用 `Van*` 组件与主题 token。
- 新页面按 6.1 的四步落地，路由一律引用 `Routes` 常量（禁止在调用处散写字符串路径）。
- 金额、时间、枚举的格式化逻辑优先「照抄 web 的规则」。

**MUST NOT**

- 不改 `web/`（真相源，只读比对）；不在 `webview-APP/` 里写原生逻辑。
- 不臆造接口、字段、枚举——拿不准就去 `api/` 核实。
- 不在业务代码里硬编码颜色（会破坏深色主题）。
- 不随意升级 Kotlin / Compose / AGP 版本（会打破编译器配对）。
- 不擅自用 `git` 恢复文件：**若读写导致乱码或缺失，先问用户**（用户明确定下的规则）。

### 7.2 样式复刻口径（像素级一致的关键）

| 规则 | 说明 |
|---|---|
| **`1rem = 16px`** | 本工程没有 flexible.js，rem × 16 换算成 dp，**小数照抄** |
| **文本行盒留白** | Compose `includeFontPadding = true` 会多加行盒留白导致小文本偏下；需精确居中时用 `BasicText` + `PlatformTextStyle(includeFontPadding = false)` + `LineHeightStyle(Trim.Both)` |
| **阴影** | web `box-shadow` → `Modifier.cssShadow(...)`（`ui/common/CssShadow.kt`） |
| **网格** | web `grid repeat(N, 1fr)` → `chunked(N)` + `Row { weight(1f) }`，末行补 `Spacer` |
| **按下反馈** | `graphicsLayer { scale }` |
| **`van-cell-group inset`** | web 用 `.app-card` 覆写成 12px 圆角（覆写 Vant 默认 8px），原生沿用 12 |
| **`Empty` 组件** | Vant4 只认 `image / description / default` 插槽，`#icon` 会被丢弃；`<img src="*.svg">` 无 `fill` 会渲染成纯黑 |
| **滚动条** | 需要隐藏时用 `Modifier.horizontalScroll` + 隐藏指示器，对齐 web 的 `::-webkit-scrollbar` 处理 |

### 7.3 金额与数值（最易出静默错误）

- web 大量使用「分/整数化、`Math.round(x*100)/100`、`Number()`」。原生侧**不要用 Double 直接累加**，用 `BigDecimal` 或整数分。
- **汇率口径**：约定「每 100 外币 = rate 人民币」，所以 `人民币 = amount × rate ÷ 100`。
- **浮点噪声**：直接 `trunc(x*10000)/10000` 会把 `9.1132`（内部是 `9.1131999…`）截成 `9.1131`。正确做法是**先清噪声再截断**（web 侧为 `Number(x.toFixed(6))` 后再 trunc）。
- **`fixed2()`**（固定资产域）**无千分位**，不要用通用的 `Money.format`。
- 展示位数：多数金额保留 4 位不四舍五入（`formatMoney`），`formatAmount` 显示原币 2 位——**按页面照抄，不要统一**。

### 7.4 时间与时区

- web 全程用 dayjs 的**本地时区**语义。
- 后端字段常见 `trans_date.slice(0,10)` 这类字符串截断取日期；原生若改用 `LocalDate` 解析，要保证**结果一致**（否则跨时区会错位一天）。
- 日历类页面的「今日 / 选中态」判定，务必与 web 用同一套「今天」定义。

### 7.5 命名与字段

- 后端返回 `snake_case`；web 前端有时兜两套命名。原生在 Repository 里**显式映射**，不要靠反射或字符串拼。
- **改动模型字段名要全仓 grep 旧引用**（历史踩坑：`Bill.statusLabel` 改名 `statusText` 撞了旧屏 `BillListScreen`）。
- 枚举/文案（如固定资产状态「使用中/已报废/已出售/已遗失」）要与 web **逐字一致**，不要自作主张改词。

### 7.6 生命周期与状态

- **导航目的地的状态必须 `rememberSaveable`**：`Routes.MAIN` 是单目的地承载四个 tab，普通 `remember` 在返回时会被重置。
  （`rememberScrollState` / `rememberLazyListState` 内部已是 saveable。）
- **KeepAlive 对齐**：web 有 11 项 `cachedViewNames`，返回列表页时**不重拉数据、只 patch 变更**（`useFlowSync`）。原生对应做法是共享状态 + 按需刷新——否则每次返回都转圈刷新，是体验倒退。
  注意：**tab 根页面离开再回来重置是 web 的原生行为**，别当成 bug 修。
- ⚠ **`VanPullRefresh` 必须传 `isChildAtTop`**（默认 `true` 会导致任意位置下拉都刷新且滚不回顶部）：
  - `LazyColumn`：`firstVisibleItemIndex == 0 && scrollOffset == 0`
  - `Column + verticalScroll`：`scrollState.value == 0`
- 列表触底加载用 `snapshotFlow { lastVisibleIndex }` + `requesting` 防重标志。

### 7.7 交互与弹层

- Vant 靠 DOM 顺序决定同 `z-index` 的叠放；Compose 里 Popup/Dialog 是独立 Window，天然盖住上层——**要保证「选择器面板」在「表单弹层」之上**，别复刻出遮挡 bug。
- 页面过渡动画：web 的 `name="fade"` / `app-slide-up` → Compose `slideIn/slideOut/fade`，方向要对齐。
- 多层弹层关闭时注意状态回收（`show = false` 后要清理内部输入状态）。

### 7.8 有意保留的 web 怪癖（**照抄，不要「修正」**）

以下都是 web 的真实行为，已刻意复刻。除非产品明确要求，否则**不要改**：

| 位置 | web 行为 |
|---|---|
| 金额配色 | Home 收入=红、支出=绿；Finance 总支出=红、总收入=绿；**Fund 收益正=红、负=绿**（反直觉，但两端一致；默认规则为「红收绿支」） |
| 理财收益 | 负值**不显示负号，只变色**（`ui/report/FundEarningsScreen.kt`） |
| 未定义的 CSS 变量 | 少数地方 web 传给 `van-notice-bar` 的颜色变量未定义 → 背景实际透明；原生按**实际渲染**复刻 |
| 编辑资料文案 | 弹窗写「长度 3-20 位」，后端 Joi 实为 `min(2).max(10)` → 输入 11–20 字会被后端拒（**待产品拍板**） |
| 卡片类型 | `credit ⇄ debit` **不可改类型**；`sharePoolId` 必须走 `POST /card/pool/assign` |
| 账单更新 | `CardBill.update` 只允许 `remindSwitch / remindDays`（额度由 CreditCore 唯一真相源计算，前端写无效） |

| 还款撤销 | 按来源流水的 `account_id`：`POST /account/credit/:accountId/reverse/repay` |
| 合并还款 | `POST /card/repay/merge` 只传 `{poolId, repayMethod, repayTime}`，后台按池结清 |
| 待办提醒 | `content === '1'` 是「出差」占位，必须过滤掉 |
| 理财保存 | web 固定发 `netValue:"0"` / `marketVal=invest` / `rate:"0.00%"` |

### 8.2 P1 —— 编译能过，但结果错

| # | 坑 | 现象 | 原因与正确做法 |
|---|---|---|---|
| **P1-1** | **`graphicsLayer.translationY` 是物理像素** | 折叠式日历「收起后日期消失」 | web 的 `translateY(px)` ≈ dp，Compose 的是**物理像素**。正确：`with(density) { -(selectedRow * 80).dp.toPx() }`。附带：`Int × Dp` 不合法，要写 `(n * 80).dp` 而不是 `n * 80.dp` |

| **P1-5** | **暗色下 Vant 别名变量被重定向** | 直接取色导致明暗不一致 | web `style.css` 在暗色下把 `--van-green`→success、`--van-blue`→primary、`--van-danger-color`→danger、`--van-danger-bg`→`#fff0f0`、`--van-green-bg`→`#f0f9eb`、`--van-orange-bg`→`rgba(255,151,106,.12)`。**这些只在暗色有值**，照抄取色时必须做暗色分支 |
| **P1-6** | **`Envelope.toResult()` 的 `ismessage` 分支** | 「是否已设置 PIN」永远判成「已设置」 | 未设置时后端返回 `status:400` 且带 `ismessage:true`，会被 `isMessage -> Ok` 判成成功。必须**直读 `envelope.status == 200`**，不要走 `toResult()` |
